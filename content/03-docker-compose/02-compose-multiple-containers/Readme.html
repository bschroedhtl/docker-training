11  Exercise: Compose container network

Two different web root folders are given

  • webA with an index.html telling that this is the A-service
  • webB for the B-service

11.1 Instructions

You shall create a file compose.yaml in this folder (next to webA and webB) for managing two nginx containers:

  • The services should be called web-1 and web-2.
  • The first should have the container_name webA, the second webB.
  • The first should be mapped to port 8081, the second to 8082.
  • The first should serve the folder webA (bind mount, like in the previous exercise), the second the folder webB.
  • Both should be assigned to a specific network called my-web-network.
  • This network should specify a specific IPAM config with the subnet 10.2.0.0/16

Hints:

  • Networks are declared in a top-level networks: section, similar to services:. Look up the syntax in the compose reference: networks (see name, driver and ipam).
  • Each service lists the networks it belongs to in its own networks: list.
  • Without name:, compose would put the folder name in front of the network name.
  • Test: http://localhost:8081 should show the A-service, http://localhost:8082 the B-service.

Only if you are stuck: a solution is in solution/compose.yaml. Start it from this folder with docker compose -f solution/compose.yaml up -d (and stop it with docker compose -f solution/compose.yaml down).

11.3 Inter-Container-Communication

Both containers reside in the same user-defined bridge network, and docker provides automatic DNS resolution for such networks. This means containers inside the same network can contact each other using either their IP addresses or their host names (=> which are actually their service and/or container names)!

Note:

  • This DNS resolution only works in user-defined networks (like the ones created by compose). Containers in the default bridge network can only reach each other by IP address.
  • Refer to https://docs.docker.com/engine/network/drivers/bridge/

We can experience this by using the ping utility.

11.3.1 Execute bash in webA

We connect our terminal to the webA container with

docker exec -it webA bash

However, the ping command is not found. So we need to install it in our container:

apt update
apt install -y iputils-ping

Finally, we are able to ping orf.at and get according ping statistics.

11.3.2 ping webB

Now we can ping our neighbour container named webB and get the following output:

root@a4074b8a929b:/# ping webB
PING webB (10.2.0.2) 56(84) bytes of data.
64 bytes from webB.my-web-network (10.2.0.2): icmp_seq=1 ttl=64 time=0.066 ms

(Your IP address may be different, e.g. 10.2.0.3 - docker picks a free address from the subnet. Stop ping with Ctrl+C.)

Also working:

  • ping 10.2.0.2 (using the internal ip address shown in your ping output)
  • ping web-2 (using the service name instead of container_name)

Question: After docker compose down and docker compose up -d, is ping still installed in webA? Why (not)?
