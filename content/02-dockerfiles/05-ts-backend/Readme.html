7  TypeScript Backend Dockerfile

7.1 Fruits Rest-Api

Given is the already known sample for the Fruits Rest-Api with following changes:

  • requests.http:
    • Introduced variable for HOSTNAME so we can edit the host name and port in a single place, if someone maps the container port to a different external port than 3000.
  • package.json:
    • added build script for the build stage
    • installed missing cors dependencies
  • tsconfig.json:
    • set outDir to dist folder so the js files will be transpiled into this folder.
    • Thus, we can keep the files required for launching the program in a separate folder, which makes copying easier.

7.2 Dockerfile

A typescript app involves a compilation (transpilation) step, which needs the full node image including npm and the TypeScript compiler. For launching the transpiled app.js file, however, only the Node.js runtime is required. Google’s distroless images contain nothing but the runtime (no shell, no package manager), so the final image is only a fraction of the size of the full node image (check the difference with docker images).

  • Refer to: https://github.com/GoogleContainerTools/distroless

So it definitely makes sense to split the Dockerfile into two stages.

7.2.1 Step 1: Build Stage

  • FROM node:24 AS builder:
    • Full node image (including npm) for building
    • Write AS in upper case like FROM, otherwise docker build prints a FromAsCasing warning
  • WORKDIR /app:
    • We will install and transpile into this folder
  • COPY ./package*.json ./:
    • First, only copy package.json and package-lock.json (if present) from the build context into the image.
    • This reduces build time for later docker builds: docker caches each build step and reuses it, as long as the files copied in this step have not changed. So npm install only runs again if the dependencies changed.
  • RUN npm install:
    • creates node_modules in app folder
  • COPY . .:
    • Now, all the rest is copied from the build context into the image, including tsconfig.json and the ts source files.
    • The .dockerignore file makes sure that a local node_modules or dist folder is not copied, since it would overwrite the folders created inside the image.
  • RUN npm run build:
    • Javascript files are transpiled into /app/dist folder

7.2.2 Step 2: Run Stage

  • FROM gcr.io/distroless/nodejs24-debian12
    • For running the javascript files, a small distroless image containing only the Node.js 24 runtime is used.
  • WORKDIR /app
    • Again, we define a common base folder for the program
  • COPY --from=builder /app/dist .
    • Copy js files
  • COPY --from=builder /app/node_modules ./node_modules
    • Copy js dependencies
  • EXPOSE 3000
    • Declare the port on which our express application listens
  • CMD ["app.js"]
    • The base image for this stage already defines node as entrypoint for the startup command, therefore we only need to specify the path to the main js file in CMD
    • Note the dist folder only exists in the build stage, we have copied all contents of this folder from the build stage to the current working directory /app.

7.3 Build, run, test

cd src
docker build -t fruit-backend .
docker run -p 3000:3000 -d fruit-backend

Test the endpoints in VS Code with requests.http. This needs the VS Code extension REST Client: click Send Request above a request.

  • GET http://localhost:3000/api/fruits should return ["apple","banana","peach"].
  • Quick check without VS Code: open http://localhost:3000/api/fruits in your browser.
